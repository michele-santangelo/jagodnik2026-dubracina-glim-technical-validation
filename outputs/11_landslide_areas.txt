The data state digest identifies the exact version of the input
shapefiles these numbers describe. If it differs between two reports,
the data changed in between and the numbers are not comparable.
Run 00_data_fingerprint.py for the per-file content hashes.

One CSV per landslide layer. Columns:

  lds_id          identifier, unique within the layer
  lds_class       type; the source-area polygon carries the x prefix
  n_polygons      how many polygons represent this landslide
  source_area_m2  area of the scarp/source polygons, blank where none
  deposit_area_m2 area of the deposit polygons
  total_area_m2   total area, the published lds_area field
  sum_shape_area  the same total recomputed from Shape_Area here
  geometry_m2     planar area of the polygons, for reference
  depth, uncert   thematic attributes, constant within a landslide
  cluster_id      overlap cluster, NA where not applicable

lds_area is ellipsoidal, as Shape_Area is; geometry_m2 is planar on
the layer CRS and runs about 300 ppm larger. See script 03.

The GIS instruction for the Usage Notes, in QGIS expression form,
for users who prefer to recompute it rather than read the field:

  sum("Shape_Area", group_by:="lds_id")

and, to obtain one record per landslide, dissolve on lds_id or use
Processing > Vector geometry > Dissolve with lds_id as the field.
