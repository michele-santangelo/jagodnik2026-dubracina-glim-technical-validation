The data state digest identifies the exact version of the input
shapefiles these numbers describe. If it differs between two reports,
the data changed in between and the numbers are not comparable.
Run 00_data_fingerprint.py for the per-file content hashes.

Every offending record is keyed by a STABLE attribute identifier, because
shapefile feature ids are positional: deleting one record renumbers every
record after it. The keys are (lds_id/lds_class) for the landslide layers
and gm_id for the geomorphological layer. The rockfall layer has no usable
key, since Id is 0 for all 486 records, so it is located by centroid.
Columns marked fid* are positional hints only, valid for the current files.
Tolerances: overlap > 1.0 m2, segment < 0.1 m,
spike angle < 3.0 deg, degenerate area < 10.0 m2,
sliver shape index > 6.0, near-duplicate IoU > 0.98.

E - Overlaps between different landslides of the same generation

superimposed: a superposition is what defines a different generation.
Overlaps here are therefore either digitising errors or landslides that
belong in different generation layers.

F - Source area and deposit of the same landslide
-------------------------------------------------
The two polygons should share a boundary: no overlap, no gap. An overlap
double counts the area; a gap leaves a strip of unmapped ground between
the scarp and the deposit of one landslide.
